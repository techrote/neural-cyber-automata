run files, seed derivation, scenario partitions and plugin admission. It does not
claim trained control, Rapier behaviour, runtime export performance or owner feel
acceptance.

The test duration is a conformance-run observation, not an inference or game
throughput benchmark. Installation, CLI and cross-platform workflow checks are
covered separately by the enclosing package task.

Boundary checks cover unknown fields/versions, duplicate JSON keys, nonfinite
values, boolean/numeric confusion, missing masks, invalid part references,
reserved channels, local/global visibility, evaluator separation, exact expiry,
sequence replay, source observation substitution, reset, slot reuse, takeover,
morphology changes and mount replacement. Consumption checks repeat admission
validation and preserve distinct request, admission, applied effort and passive
motion values. An admitted out-of-range replacement cannot bypass those checks.

Legacy tests preserve ACT003 wire/direct field names, legal diagonal component
inputs, v1 integral-float envelope compatibility, exact four-channel mappings,
nonzero reserved-slot rejection and neutral cancellation without firing or
release-to-launch. A v1 action is never implicitly upgraded to ACT004 v2.

Run checks race 12 writers for one run ID, producing exactly one immutable
record and 11 explicit refusals. Twelve distinct concurrent run IDs remain
independent. Tampered content, duplicate JSON fields, missing failure reasons,
invalid source identity, private absolute artifact paths and Windows reserved
file names are refused. Deep configuration mutation cannot change an existing
record. Resume uses a new run ID with fresh-episode lineage. Unmeasured physical
performance remains null.

Named random streams do not alter Python's process-global random state.
Scenario-family partitions reject overlap and unknown-family access. Their
hashes describe the declared split; they do not prove an evaluator remained
sealed during a research campaign.

## Failed attempt and correction

An initial import failed because an artifact's `sha256` field collided with the
base record's computed `sha256` property. The artifact field is now explicitly
`content_sha256`; the computed record hash and artifact byte hash have different
meanings. Import and round-trip tests pass after that correction.

An early draft used an inclusive command deadline. Reading both current host
admission checks established the exclusive comparison: source tick plus lease
must be greater than the current owner input tick. The implementation and the
boundary tests were corrected before the reported test run.

## Limits and operational details

Profile JSON includes one artificial two-part fixture and three sampled ACT003
metal mappings. None is an ACT004 trained/qualified mechanics profile. Broad
legacy observation storage bounds are not a learned policy's normalization.
Structural JSON Schema cannot express every runtime cross-field check; the
strict Python constructors remain required.

Run publication uses an atomic hard link from a fully written, flushed temporary
file. Existing records are never replaced. Filesystems without hard-link support
fail visibly; this implementation does not claim atomic publication there.
Content hashes detect accidental alteration relative to the stored receipt;
they are not signatures or proof against someone replacing both content and
its hash. The store creates immutable files but is not an external archival
service or an exact mid-episode resume mechanism.
