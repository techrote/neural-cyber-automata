# Demonstration capture and consumed-request replay

This record supports [T-104 / #14](https://github.com/techrote/neural-cyber-automata/issues/14).
The capture and replay implementation executed against the accepted ACT-004
owner, Rapier and native material runtime. T-102 was accepted on learner base
`df0deea16b6b6ad1d5494e31c0256c9b48b0c675`; the T-104 and T-103 controller
candidate bytes were still uncommitted at these captures. Their exact source
file hashes are stored inside every episode. This is candidate implementation
evidence, not a substitute for final-head CI and merge verification.

## Implemented and checked

The [capture/data API](../../configs/datasets/README.md) separates dispatch view,
original source view, optional sampled request or residual, original submitted
packet, owner admission, per-base-tick consumption, actual aggregate actuation,
unavailable passive wrench and actual motion. It records source, policy, profile,
seed, configuration, host build, tick/wall timing, intervention labels and final
reason. Six-tick repeats preserve every receipt, including held and expired input.

Original source observations remain original even when submission is delayed.
A host test creates a request from tick 0, advances without submitting it until
tick 3, and verifies that policy features still come from tick 0. Replay changes
only issued identity peers, consumes at tick 3 and preserves observation age,
sequence and lease. Rejected duplicates do not become new learning samples just
because the previously accepted request remains held.

Cancellation and source takeover call owner cancellation and split recurrence.
Actual velocity and part poses remain unchanged at cancellation. Joint
angle/error/speed remain loaded while control targets become zero. A full reset
produces a different run at tick 0, zero initial velocity and charge, and refuses
the earlier run's packet. Actor/profile/morphology/mount/topology changes are
marked when observable; unsupported hidden mount mutation is not inferred.

The policy iterator filters its own-state/ray view independently of stored audit
observations. Explicit goal context is supplied by the caller; evaluation
outcomes stay in a separate mapping. Human corrections and model replacements
retain their labels. PPO eligibility refuses corrections, replacements, missing
likelihood, unknown source views, mixed consumption, lost receipts and denied
requests. Likelihood attaches to the sampled request or latent, not the applied
impulse. Actual source-transfer fixtures are labelled scripted; no human input
session or live model service is claimed.

## Bounded actual captures

Every run used actor `jev`, six 60 Hz base ticks per decision, the source-anchored
12-tick helper lease, the actual authored profile and the same declared replay
tolerance. Each capture had an upper budget of 100 decisions and 120 seconds.
There was no optimization or paid service. The three final captures contain
**51 decisions and 296 base receipts**, including passive intervals.

| Run | Seed / requested task | Decisions / ticks | Capture and replay | Independent task outcome |
|---|---|---|---|---|
| `t104-control-boundaries` | 7 / source lifecycle fixture | 7 / 32 | Passed; 5 admitted requests, 2 denied attempts omitted from causal replay, 2 owner cancellations | Task quality not measured |
| `t104-jolt-48` | 1703 / +48-cell directed hop, pace 0.8 | 22 / 132 | Passed; 22 admitted requests | Controller estimate succeeded; final distance 2.960229 cells, speed 0.037949 cells/s |
| `t104-jolt-20-unsuccessful` | 7 / +20-cell directed hop, pace 0.75 | 22 / 132 | Passed; 22 admitted requests | Did not reach the arrival criterion in this budget; controller still running, final distance 14.925573 cells, speed 46.072190 cells/s |

The short-goal run demonstrates why pipeline completion is not a task-success
label. A target closer than the qualified +48-cell scenario can overshoot under
the authored pulse and subsequent rebound behavior. The unsuccessful trajectory
is retained with its outcome; it is not silently filtered out or relabelled.
The local controller success estimate is still distinct from owner feel approval.

All captured scenario families are assigned to evaluation. Training and tuning
partitions are empty. There are 49 eligible imitation rows and **zero on-policy
PPO rows** in the three final artifacts, because their sources are scripted and
do not supply policy sampling likelihoods. This is not a training result.

## Declared replay comparison

Replay compares actor and per-part position, velocity, angle and angular
velocity, selected discrete local state, copied cell patches, consumed action
state, owner tick/material schedule and aggregate linear/angular impulse/energy.
It does not have whole native-world state or a separately exposed passive wrench.
Each submitted accepted packet has an explicit original/replay run, epoch and
observation identity pair; that identity evidence is separate from pose errors.

| Quantity | Declared absolute tolerance | Maximum observed error across the three replays |
|---|---|---|
| Position | 0.001 cells | 0 |
| Velocity | 0.001 cells/s | 0 |
| Rotation | 0.0001 radians | 0 |
| Angular velocity | 0.001 radians/s | 0 |
| Applied scalar/vector receipt components | 0.001 in each recorded component's unit | 1.021406e-14 |
| Owner tick, copied action, selected discrete state and cell patch | Exact comparison | No mismatch |

The boundary replay performed 968 numerical comparisons. Each Jolt replay
performed 3,720. The full set of 8,408 comparisons passed the predeclared bounds.
These results support compatible-build copied local trajectories and input
timing. They do not establish full-state identity, equal wall time, cross-platform
exact replay or real-time replay. Current causal replay deliberately requires
the stepped lane and rejects runtime/profile drift or incomplete traces.

## Preserved failures and limits

The first actual capture stopped after one decision and six base ticks with a
`TypeError` when resubmitting an immutable nested packet. Its original failed run
receipt and 10,587-byte partial episode remain in the external development
archive. Transport values are now explicitly copied to ordinary JSON before
submission. The partial file predates the final record schema and is preserved
as raw development evidence, not inserted into the eligible v1 dataset.

An early cancellation assertion incorrectly required the commanded joint target
to remain unchanged. The actual owner correctly cleared that target. The check
was corrected to require retained physical angle/error/speed and zero control
target, and the actual host suite passed. This was a test assumption correction,
not an unauthorized host change.

This evidence does not claim real-time causal replay, arbitrary owner topology
mutation, full-state policy inputs, learned-policy performance, live human/model
demonstrations, statistically established success rates or owner feel acceptance.
The implemented interfaces retain those distinctions for subsequent tasks.
