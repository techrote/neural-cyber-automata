## Scope and source authority

Godot/native/Rapier host. This record qualifies persistent adapter operation for
two selected physical profiles. It does not establish learned skill quality,
desktop schedule parity, Windows runtime performance or owner feel acceptance.

was reconciled against the live host before implementation. Cybersand

## Failed attempts and review corrections

An initial resource import used a default sandbox environment that could not
create Godot's user cache and could not open required local sockets. Setup now
uses scoped XDG data/config/cache directories, and live tests run where loopback
is available. The failed import is not counted as host conformance evidence.

The first persistent handshake compared Godot's structured version dictionary
with the CLI version string. The handshake now validates the actual fields and
locked runtime identity. Two initial ACT003 tests also exposed that its terminal
suspension increments the input epoch. The client now permits that exact one-step
terminal revocation, while continuing to reject unexpected lifetime changes.
The corrected sampled tests passed against the actual arena.

Independent peer review reproduced malformed reset actor values causing a
GDScript error/transport timeout and realtime horizons losing their final state
through the ordinary step API. Exact actor type/integer checks now precede casts,
and a late realtime step returns the already-completed terminal interval once.
Both corrected paths have real-host regression tests in the final run.
The peer re-reviewed the final bridge and Python client hashes listed below and
reported no further blocking finding in the three changed areas.

Review also identified blocking output on the physics thread. Godot's official
[StreamPeer documentation](https://docs.godotengine.org/en/stable/classes/class_streampeer.html#class-streampeer-method-put-data)
states that `put_data` may block until delivery. The bridge now uses
`put_partial_data` with one bounded output packet and a two-second stalled-output
deadline. Normal live request/response paths passed after this change. Exhaustive
kernel/socket backpressure stress is unmeasured; the source/API correction is
not presented as such a stress result.

## Explicit limits

ACT004's accepted local view supplies aggregate actor impulse/torque and actual
part motion, but no separate passive/contact wrench decomposition. Those receipt
fields remain unavailable. ACT003 metal's passive force/torque is a sampled-lane
receipt, never a physical substitute.

Terminal suspension clears the current physical wire action. The adapter marks
that terminal action unavailable while retaining real motion/impulse observations;
it does not relabel current state as a complete force receipt. ACT004 also defines
no task reward: returned zero is explicitly `no_task_reward`, and says nothing
about skill success.

The public API offers complete reset-based graph replacement and initial actor
configuration. Arbitrary independent body replacement, injected disturbances,
support removal and authored assist mutation are absent. Those facilities were
not manufactured by editing host internals. Native usable requests remain bounded
wire inputs to the existing gameplay owner.

Windows instructions are prepared but local Windows execution, desktop timing,
learned-control speed and owner feel remain unmeasured. No GPU, paid model call,
weight training or host-runtime modification was used for this task.
