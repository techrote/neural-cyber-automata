## Observations, masking and information reach

The shared schema supports up to eight part slots and seven distinct connections. The current actual
profiles exercise two, three and five parts. Array capacity does not qualify physical assemblies at every
size from one through eight, or arbitrary multigraphs with more than seven connections.

Each part supplies 20 numeric values: its own motion, orientation, explicit-goal displacement in its own
frame, authored dimensions, mass, rest offset and angle, and a small physical-role indicator. Each
connection supplies 22 values for its type, authored geometry and assistance, effective limits and
observed relative motion. Separate validity masks distinguish an unavailable measurement from a valid
stationary zero. Separate present and active masks distinguish padding from a detached part. Inactive part
and connection values and their validity are zero, so hidden sensor payloads cannot enter through a masked
slot.

The root alone receives 33 values covering contact, rig rays, resources, mechanics and previous requested
action, with separate validity. Actual `wall_left` and `wall_right` are distance measurements, not contact
booleans. Four command values convey explicit pace, tolerance, remaining observable deadline and original
source age. The goal is caller context; the adapter does not search the scene for a target. Actor names,
run/part IDs and profile hashes remain receipt metadata and are absent from numeric policy input. Reward,
evaluator success, other actors, global scene queries and the cell patch are excluded. A separate passive
wrench is unavailable and is not reconstructed from aggregate motion.

The padded candidate receives all permitted own-part slots immediately. Each graph node receives only its
own current part values and the explicit command; the root gets its additional local sensors. Synchronous
messages cross only active authored edges. A one-round root cannot depend on the Ripper roller two joints
away; two rounds can. Earlier recurrent memory may carry information from earlier decisions, so the
two-hop statement applies to *current* inputs. There is no global pooling. Node permutation and gradient
reach tests verify this implementation property without a game rollout or optimizer update.

## Candidate size and state ownership

The optional CPU implementations are in [models.py](../../src/nca/controllers/morphology/models.py).
Importing the admission gate, profile adapter or conformance runner does not import Torch. No learned
morphology weights are supplied.

| Property | Padded recurrent candidate | Shared graph candidate |
|---|---:|---:|
| Numeric padded input | 855 values | Same allowed sensors, locally routed |
| Trainable parameters | 13,048 | 13,192 |
| Hidden values | 32 FP32 | Up to 256 FP32, 32 per part |
| Message rounds per decision | 0 | 2 |
| Dense multiply-accumulates per decision | 12,838 | At most 187,840 |
| Common parameter ceiling | 14,000 | 14,000 |
| Common dense MAC ceiling | 200,000 | 200,000 |
| Common hidden-state ceiling | 1,024 bytes | 1,024 bytes |

Parameter counts differ by about 1.1%. The graph uses more actual arithmetic and memory. These are
declared common ceilings and equal future game-collection allocations, not identical FLOPs or a pure
topology ablation. The MAC estimates exclude nonlinearities, dispatch and allocation; they are not
measured runtime latency. The padded implementation uses a 10-value projection and 32-value GRU. The graph
uses shared 32-value node states, 16-value messages and a root readout.

Weights can be shared across instances, while hidden state, action history, invocation IDs and lifetime
fences are independent. Padding neither advances recurrence nor contributes a training loss. Inactive
graph states are zeroed before messages and after recurrence, including biases. Goal cancellation,
part/connection changes and control, source or observed mount-generation changes clear state and retire
the old invocation. A new physical incarnation resets the tick clock; retired incarnations cannot resume.
Same-incarnation time or authority rollback stays refused after cancellation. Changing a full physical
profile requires a real host reset. There is no speculative hidden state remapping.
After a known mount generation, an unavailable sample refuses instead of erasing the known fence; only a
new physical incarnation can begin unknown again. Delayed inference checks the goal deadline against the
current tick. Every packet's lease is also capped at that fixed deadline using the original source tick.

The preparation runtime labels every numeric decision `accepted_unqualified`, with deterministic sampling
mode and `log_probability=None`. A decision is bound to the original local source digest and can be
dispatched once. A changed view, cancelled decision, reused decision or command-construction/transport
failure clears local state and requires actual owner cancellation. An all-zero action is not used as a
substitute release step. If cleanup is unconfirmed, fresh goal IDs and source generations remain blocked.
While a command may be live, changing goal, source, mount or topology also requires owner revocation first.
A valid cancel receipt must identify the same incarnation, advance owner generation and preserve the
observed time/authority high-water marks. A validated tick-zero new world reset can also retire uncertainty
about the previous world. Merely returning from a cleanup callback cannot release that latch.

The renewed execution audit found that native `step_packet` returns refused admissions inside its
completed receipts. Dispatch now validates those admissions, original requested actions and available
per-tick consumed actions before retaining recurrence. Missing, replaced, malformed or changed-owner
receipts clear local state and invoke actual owner cancellation. At a native episode end, the last action
readback remains explicitly unavailable after revocation; local recurrence is erased and a new physical
episode is required. A dedicated terminal identity validator retains the strict original schema, integer
counters, observation stamp and pinned physical structure checks without admitting a suspended actor to
inference. Cancellation diagnostics also require the new owner generation's observation stamp and the
native revocation of requested motor targets while measured joint state stays fixed.
These corrections leave the declared candidate models, capabilities, cadence, split and budgets unchanged.

Synthetic part detachment and supplied mount-generation tests establish these software fences. The four
selected profiles do not publish an independently replaceable mount object generation to this adapter;
absence remains `None`. Actual usable mount lifecycle evidence in [T107](2026-10-19-t107.md) is separate.
No arbitrary damage, mass, assist, support-removal or mount-replacement operation was added to the
accepted host, and no recovery qualification is inferred from the synthetic tests.
